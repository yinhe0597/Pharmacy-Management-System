# 20 二期就诊模块规划

> 目标：将系统从「药房进销存 + 处方调配」升级为「医生看诊 → 医嘱 → 诊疗执行 → 合并收费 → 药房发药」的诊疗一体化闭环。
> 原则：后端 + 数据库先行，前端随后（docs/17 已完成一期前端 P0-P6，本模块在其上增量扩展）。

---

## 一、核心业务内容（按看诊流程）

### 1. 就诊管理（`visits` 表）
- 挂号/分诊：就诊号、患者、科室、医生、就诊类型（`outpatient` 门诊 / `inpatient` 住院 / `refill` 出院带药）。
- 状态机：`waiting` 待诊 → `visiting` 就诊中 → `finished` 已结束 / `cancelled` 退号。
- 处方 `source` 同步扩展为门诊/住院/带药（当前仅 `manual`）。

### 2. 病历（`medical_records` 表）
- 主诉、现病史、既往史、体格检查、体征（体温/血压/脉搏，跟诊护士录入）。
- 结构化诊断：关联 ICD-10 `diagnosis_codes`（处方 `diagnosis_code` 已落库，病历可多诊断）。
- 病历 → 就诊 → 处方（医嘱）关联。

### 3. 医嘱与处方联动（已就绪，增量）
- 医生端开立（复用 `POST /prescriptions`，带 `patient_id`/`source`/`diagnosis_code`）。
- 跟诊护士核对医嘱（`verify-order` 已实现）→ 药师审核 → 药房调配发药（全链路已实现）。

### 4. 诊疗项目执行
- 复用 `clinical_services`；新增执行登记（visit_id + 执行人 + 执行时间 + 结果）。

### 5. 合并结算（`charges` + `charge_items` 表）
- `IPricingService.CalculateBill`：挂号费 registration + 诊查费 + 治疗费 + 检查费 + 药费合并。
- 收费状态机：`pending` 待收 → `paid` 已收 → `refunded` 已退；与药费计费（charge_records）互通/并存。
- 退费复用红冲（void）与负金额冲正能力。

### 6. 患者就诊历史
- 患者详情聚合：就诊列表、病历、处方、费用（`patient-charges` 报表已有）。

### 7. 统计报表
- 就诊量（科室/医生/日）、收入构成（挂号/诊疗/药费占比）、诊断分布。

## 三、实施计划（后端+DB 先行）

| 阶段 | 内容 | 交付 |
|------|------|------|
| S1 | 迁移：`visits`、`medical_records`、`charges`、`charge_items`（patients 已有） | 表结构 + 索引 |
| S2 | 就诊域：挂号/分诊、状态机、列表（按患者/医生/日期） | visits API |
| S3 | 病历域：主诉/现病史/诊断结构化、体征录入 | medical_records API |
| S4 | 结算域：`CalculateBill` 多费用项合并 + 收费状态机 + 退费 | charges API + port 扩展 |
| S5 | 处方联动：`source` 扩展（outpatient/inpatient/refill） | 处方创建支持 source |
| S6 | 前端：就诊工作台（叫号）、病历编辑器、收费台、患者就诊历史 | 页面 |
| S7 | 报表：就诊量/收入构成 | 报表 API + 图表 |

## 五、风险与注意

- **计费双轨**：一期 `charge_records`（药费）与二期 `charges`（合并单）并存期间需口径统一，报表合并时注意去重。
- **契约稳定性**：port 接口扩展 `CalculateBill` 需同步契约测试（docs/07 §4）。
- **数据库版本**：本地联调请使用 PostgreSQL 14-16（18.x 存在 GORM INSERT 回归，见 docs/00）。
