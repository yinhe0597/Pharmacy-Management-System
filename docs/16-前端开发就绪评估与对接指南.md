## 三、认证与角色（前端对接要点）

| 角色 | 主要权限 | 前端菜单建议 |
|------|---------|-------------|
| `admin` 管理员 | 全部 + 用户管理 | 全部菜单 + 系统管理 |
| `pharmacy_director` 药房主任 | 全部（含用户管理/审核） | 全部菜单 |
| `pharmacist` 药师 | 药品/库存/处方/审核/特殊药品/报表 | 全部菜单（含审核） |
| `doctor` 医生 | 处方开立/患者写/调配/核对/药学服务 | 开方、处方执行、患者、药学服务 |
| `clinic_nurse` 跟诊护士 | 患者管理/核对医嘱/辅助开方/诊疗计费 | 患者、开方（辅助）、医嘱核对、计费录入 |
| `pharmacy_nurse` 药房护士 | 查询/耗材领用补发/处方执行/辅助核对收费/药学服务 | 药品查询、库存/领用、处方执行、计费核对、药学服务 |
| `buyer` 采购员 | 采购/供应商 | 采购 |
| `finance` 财务 | 报表 | 报表 |

- 登录：`POST /api/v1/auth/login` → `data.token`，后续请求头 `Authorization: Bearer <token>`。
- 登出：`POST /api/v1/auth/logout`（无状态，客户端丢弃 token 即可）。
- 密码修改：`PUT /api/v1/auth/password`。
- 前端建议：401 时统一跳登录页；403 时提示「无权限」；409 时提示「状态冲突，请刷新」。

## 五、前端须知（已知边界）

1. **`patient_id=0` 表示未关联患者**：手工处方可无患者档案；开方时建议强制选择患者（后端已支持回填）。
2. **冲正/红冲记录是负金额行**：`charge_records.amount<0` 为退药冲正或红冲；`voided=true` 的原单不再计入金额。
   合计一律以 `amount` 字段为准（混合计价下 `quantity×unit_price ≠ amount`，冲正行 `unit_price=0`）。
3. **无 refresh token**：token 有效期 720h，过期需重新登录；前端可自行实现静默重登。
4. **预警无推送**：`GET /inventory/expiry-warnings|stock-warnings` 轮询即可。
5. **金额单位为「分」（int64）**：前端展示需自行除以 100；禁止浮点运算，建议 decimal/分字符串处理。
6. **时间格式**：RFC3339；日期（效期）为 `YYYY-MM-DD`。
7. **类型生成**：可用 `swagger.json`（`docs/swagger.json`）生成 TS 类型（openapi-typescript / openapi-generator）。
8. **敏感字段**：患者卡号/电话、计费记录仅限药房人员与报表角色可见（后端已按角色收窄，前端菜单同步隐藏）。
