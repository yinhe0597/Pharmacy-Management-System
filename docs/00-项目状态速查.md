## 项目
- **定位**：药房进销存 + 处方调配系统。后端 Go 1.26 + Gin + GORM + PostgreSQL 14 + swaggo + JWT + robfig-cron；前端 Vite5 + Vue3 + TS(strict) + Element Plus + Pinia + Vue Router + Axios。
- **形态**：monorepo——根目录为 Go 后端；`pharmacy-web/` 为前端 SPA。
- **Git**：远程 `https://gitee.com/luo-yinhe/pharmacy-management-system.git`；本地分支 `main` 跟踪 `origin/master`；推送 `git push origin main:master`；作者 vincentluo <yhkjsj@foxmail.com>。
- **提交惯例**：每次提交必须同步更新主页 `README.md`（docs/06 §8）；推送前若远端有新提交先 `git pull --rebase origin master`。

- **安全基线（第三/四/六轮）**：`release` 模式下弱/占位 JWT 密钥与「仍有默认口令 admin123 的启用账号」均拒绝启动（`internal/server/startup.go`，可用 `YF_AUTH_ALLOW_DEFAULT_PASSWORDS=true` 仅演示豁免）；`release` 模式下 CORS 含 `*` 亦拒绝启动；`server.trusted_proxies`（`YF_SERVER_TRUSTED_PROXIES`）默认不信任任何代理头；CORS 白名单留空 = 不下发 CORS 头（fail-closed，回显 Origin 时带 `Vary: Origin`）；Swagger 仅非 release 注册；**每请求复查用户状态/角色/登录名/姓名（停用/降权/改名即时生效）**；**JWT 令牌可吊销**（`users.token_version`，000039；改密与管理员重置口令即作废该用户全部存量 token）；写操作统一审计（`middleware.AuditWrites` → `operation_logs`，记录**登录名**，用 `context.WithoutCancel` 防「读到 200 立刻 RST」的审计规避）；登录限速（IP+用户名双维度桶，4 KiB body 上限、桶数硬上限）；Nginx 登录限速 + 安全响应头；后端 `SecureHeaders`。
- **角色（8）**：admin / pharmacy_director / pharmacist / doctor / clinic_nurse(跟诊护士) / pharmacy_nurse(药房护士) / buyer / finance；RBAC 按路由组强制（server.go Groups：DrugAdmin/Pharmacy/Clinical/Purchase/Report/Billing/Patient/PatientRead/Charge/UserAdmin）。
- **关键正确性（第六轮修订）**：金额整数分；**效期为 date-only 口径**（FEFO 与过期锁定统一用 `CURRENT_DATE`，当天到期不算过期；`todayNow()` 归一化到 Asia/Shanghai 零点）；FEFO+预占/实扣/释放（行锁+条件更新）；处方版本号乐观锁；**状态流转不抹除他阶段审计痕迹**；**GORM 更新一律 `Omit(主键/编码/创建时间).Select("*")`**（否则零值丢失：药品无法停用、编码被毁）；麻精双人核对(4003)/拆零双人复核(2013)；麻精**限量拒绝 `days<=0`** 且混合开方按「最严」归类；退药冲正与退药同事务；**自动拆零处方的退药回补到拆零行而非整盒行**。
- **统一记账口径（000040）**：`charges`（结算单）+ `charge_items`（费用行）是**唯一记账凭证**；`charge_records` 降级为「应收计费项目源」（+= `visit_id`），只被结算单按就诊精确归集，**不被任何报表直接统计**。`charge_items.source_record_id` 回溯来源，消除 `item_id` 多态歧义。`CalculateBill` 三来源：①已发药处方快照（退药按 `ReturnedQuantity` 回算净额）②本就诊非处方来源的 charge_records（排除 `ref_type='prescription'` 防重复）③系统设置默认挂号/诊查费。
- **业务单号（000041）**：`internal/pkg/seq` 号段表（`doc_segments`），单条 `INSERT..ON CONFLICT..RETURNING` 原子申请 256 个号，进程内独占区间 → **5~20 副本多实例下全局唯一**。格式 `<prefix><yyyyMMddHHmmss><8 位绝对序号>`，保留时间可排序性，与旧格式长度不同故不与存量冲突。`Next` 返回 error——宁可失败也不产生重复单号。启动时由 `server.NewApp` 注入。
- **验证命令**：`go build ./...`、`go vet ./...`、`go vet -tags=integration ./...`（集成测试需 PG，CI 跑）、`go test ./cmd/... ./internal/...`、`gofmt -l .`、`golangci-lint run ./...`（.golangci.yml 排除 pharmacy-web）。
- **环境**：`make db-up`（docker-compose PG16+迁移）；种子用户 8 个（密码 admin123）；Swagger `/swagger/index.html`；CORS 由 `server.cors_allow_origins` 配置；**`.env` 变量名统一 `YF_` 前缀**（`YF_AUTH_JWT_SECRET` / `YF_DATABASE_PASSWORD`），生产脚本与开发 Makefile 共用同一套。

## ⚠️ 已知坑位（务必牢记）
- **GORM 列名错位（42703 元凶）**：Go 字段 `VPBBatch` 被 GORM 命名策略转成 `vpb_batch`（V-P-B 错位），
  数据库列是 `vbp_batch`。已用 `gorm:"column:vbp_batch"` 显式修复（model/drug.go、model/reference.go）。
  **新增含多连大写缩写（VBP/VPD/FEFO 等）的字段时，必须核对 GORM 生成的列名与迁移 SQL 一致**；
  可用 `zz 全模型审计`（internal/server 下临时程序，schema.Parse vs information_schema）校验 0 错位。
- 本地 PG16 便携版在 `%TEMP%\pg16\pgsql\bin`；数据目录 `.pgdata16/`（已 gitignore）。
  **本地开发统一走 Docker：`make env-init` 生成含随机密钥的 `.env`（JWT + 数据库口令）→ `make db-up` 起库并迁移**；
  `configs/config.yaml`（gitignored）的数据库口令需与 `.env` 的 `YF_DATABASE_PASSWORD` 一致。
- **迁移一律用 `scripts/migrate.sh`（`make db-migrate`）**：`schema_migrations` 版本表 + 增量执行；
  历史库（旧版全量重放方式初始化）首次升级需一次性 `YF_MIGRATE_BASELINE_TO=000032`。
- 集成测试表清空清单在 `integration_test.go` `testCleanupTables`（会 TRUNCATE 业务表，勿对生产库跑），
  由 `TestCleanupCoversAllTables` 守护：新增业务表必须同步登记，否则守护失败；
  新增业务表后须同步补入清单，否则用例间会互相污染（曾因盘点残留导致随机失败）。
  不需要清理的表登记在 `testStaticTables` 并**附原因**（如 `doc_segments` 是单调计数器，清空会使序号回退）。
- **集成测试默认连独立库 `yaofang_test`**（`YF_TEST_DB_NAME` 可覆盖）：`setupTestDB` 会
  `TRUNCATE ... RESTART IDENTITY CASCADE`，此前硬编码连开发库 `yaofang`，**跑一次集成测试即抹掉本地数据**。
  首次使用执行 `make test-db-init`（建库 + 跑完 41 个迁移，幂等）。
- **集成测试共用单个连接池**（`sharedDBOnce`）：此前每用例各自 `OpenDB` 且从不关闭，
  用例数一多累计连接数超 `max_connections`，后续用例随机报 "too many clients already"，
  把基础设施问题伪装成业务失败。新增高并发用例时请复用 `setupTestDB(t)` 返回的句柄。
- **`expiry_date` 是 DATE 列**：与 `time.Time` 参数比较时 PG 按会话时区提升为当天 00:00。
  判断效期一律用 date-only 语义（`rule.IsExpired` / SQL `CURRENT_DATE`），
  **不要传 `time.Now()` 之类的带时分秒时刻**——当天到期批次会被整日排除，且与 `LockExpired` 自相矛盾。
- **DATE 列相减不要再套 `EXTRACT`**：PG 中 `date - date` 返回的是 `integer`（已是整天数，可为负），
  不是 `interval`，套 `EXTRACT(DAY FROM ...)` 会因缺少 `extract(unknown, integer)` 重载**直接报错**，
  整个接口运行期 500（已实测）。要天数就直接相减。
- **源码必须全仓库统一 UTF-8**：`src/api/prescriptions.ts` 与 `src/api/purchase.ts` 的中文注释曾是
  **GBK 字节**混在 UTF-8 仓库中。后果连锁：UTF-8 工具读出乱码；`prettier format:check` 恒报
  「格式不合规」（**那不是格式问题**）；而 `prettier --write` 会把非法字节替换成 U+FFFD
  **不可逆销毁注释**。其中一处损坏吃掉换行，使 `batch_group` 被并进上一行注释——
  该字段是后端真实字段且 `create.vue` 正在发送，却因此脱离类型检查。
  现已由 `contract.test.ts` 的编码守卫（`TextDecoder` fatal 模式）强制把关。
- **主干分支是 `master` 不是 `main`**：两个 CI 工作流此前都只监听 `main`，
  而推送走 `master` → 流水线整体不触发，「CI 全绿」长期只是形式要求。已修正为 `[master, main]`。
- **`.golangci.yml` 必须是 v2 格式**：CI 锁定 golangci-lint `v2.1.6`（v1.x 内嵌 go/types 过旧，
  解析不了 Go 1.24+ 标准库，门槛会整体失效），而 v2 要求 `version: "2"`，
  配置不对会直接报 `unsupported version of the configuration: ""` 并退出。
  升 golangci-lint 版本时**必须同步确认配置格式**，否则等于没有 lint 门槛。
  注意 v2 把 QF\* 合并进了 `staticcheck`，门槛比 v1 更严。
