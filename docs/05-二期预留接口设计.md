# 05 二期预留接口设计

> 本文档定义一期与二期（诊疗模块）之间的**契约**。一期实现「简易版」，二期替换为「完整版」，
> 期间对外接口签名与出入参结构保持不变，保证无缝接入。
> 契约测试见 [07-测试方案.md](07-测试方案.md) §4。

---

## §1 预留原则

1. **接口签名先定**：能力出口以 Go 接口定义在 `internal/service/port`，一期直接使用其简易实现。
2. **结构稳定**：处方 API 入参结构（含诊断、科室、开方人、来源）一期即完整定义，
   一期手动填充，二期由诊疗模块自动传入。
3. **内部调用不依赖 HTTP**：`IStockService` 等接口在 Service 层直接调用，
   二期诊疗模块以**进程内调用**接入（同一进程模块化单体）或以 HTTP 暴露。
4. **数据提前留位**：`prescriptions.patient_id`、`source` 字段一期已存在，二期直接启用。

## §2 IPatientService（患者服务）

```go
// internal/service/port/patient_service.go
package port

import (
    "context"
    "time"
)

// Patient 患者档案（二期完整对象；一期仅存储标识信息）
type Patient struct {
    ID         int64     `json:"id"`
    Name       string    `json:"name"`
    Gender     string    `json:"gender"`
    Age        string    `json:"age"`
    CardNo     string    `json:"card_no"`     // 就诊卡号/身份证号
    Phone      string    `json:"phone"`
    CreatedAt  time.Time `json:"created_at"`
}

type Allergy struct {
    DrugName  string `json:"drug_name"`
    Reaction  string `json:"reaction"`
    Severity  int    `json:"severity"`   // 1轻 2中 3重
}

type MedicationRecord struct {
    DrugName  string `json:"drug_name"`
    Dosage    string `json:"dosage"`
    BeginDate string `json:"begin_date"`
    EndDate   string `json:"end_date"`
}

// IPatientService 一期提供简易实现 SimplePatientService（仅存储 Name/CardNo 字符串），
// 二期替换为完整患者档案实现，接口不变。
type IPatientService interface {
    Register(ctx context.Context, p *Patient) (int64, error)
    GetPatient(ctx context.Context, patientID int64) (*Patient, error)
    // 二期扩展（一期返回空集即可）
    GetAllergies(ctx context.Context, patientID int64) ([]Allergy, error)
    GetMedicationHistory(ctx context.Context, patientID int64) ([]MedicationRecord, error)
}
```

### 一期简易实现

```go
// internal/service/patient/simple_patient_service.go
type SimplePatientService struct{}

func (s *SimplePatientService) Register(ctx context.Context, p *port.Patient) (int64, error) {
    // 一期：仅把 Name/CardNo 冗余存到 prescriptions 表；不建 patients 表
    return 0, nil
}

func (s *SimplePatientService) GetAllergies(ctx context.Context, _ int64) ([]port.Allergy, error) {
    return nil, nil // 二期：处方审核时自动带入过敏史提醒
}
```

### 二期接入点

- 处方录入/审核时：`ps.GetAllergies(patientID)` → 过敏史匹配该药品 → 处方审核提示。
- `ps.GetMedicationHistory(patientID)` → 重复用药分析数据源。

## §3 IStockService（库存服务接口）

```go
// internal/service/port/stock_service.go
package port

import "context"

type ReserveItem struct {
    DrugID     int64 `json:"drug_id"`
    LocationID int64 `json:"location_id"`
    IsSplit    bool  `json:"is_split"` // true=强制拆零（数量按拆零单位）
    Mixed      bool  `json:"mixed"`    // true=混合发药（数量按 LDU，整盒+拆零自动分配）
    Quantity   int64 `json:"quantity"` // 强制拆零=拆零单位；混合=LDU；整盒口径=基本单位
    ItemID     int64 `json:"item_id"`  // 业务明细 ID（处方明细）
}

type ReservationResult struct {
    DrugID     int64  `json:"drug_id"`
    Quantity   int64  `json:"quantity"`
    Reserved   int64  `json:"reserved"`
    Shortage   int64  `json:"shortage"`   // >0 表示不足量
}

type DispenseItem struct {
    DrugID          int64 `json:"drug_id"`
    LocationID      int64 `json:"location_id"`
    Quantity        int64 `json:"quantity"`          // LDU
    BatchAllocation []BatchQty `json:"batch_allocation"` // 指定批次（可选，默认 FEFO）
}

type BatchQty struct {
    InventoryID int64  `json:"inventory_id"`
    BatchNo     string `json:"batch_no"`
    ExpiryDate  string `json:"expiry_date"`
    IsSplit     bool   `json:"is_split"`
    Quantity    int64  `json:"quantity"`
}

type Availability struct {
    LocationID   int64  `json:"location_id"`
    LocationName string `json:"location_name"`
    Available    int64  `json:"available"` // 可用 LDU
    ExpirySoon   bool   `json:"expiry_soon"`
}

// IStockService 一期由 InventoryService 实现（药房内部调用），
// 二期暴露给诊疗模块：开方辅助查询、开方预占、发药实扣、退方释放。
type IStockService interface {
    // refType 单据类型（prescription/...），refID 单据 ID（int64，对应数据库主键）
    ReserveStock(ctx context.Context, refType string, refID int64, items []ReserveItem) ([]ReservationResult, error)
    DispenseAndReduceStock(ctx context.Context, refType string, refID int64, items []DispenseItem) error
    CancelReservation(ctx context.Context, refType string, refID int64, items []ReserveItem) error
    GetDrugAvailability(ctx context.Context, drugID int64) ([]Availability, error)
}
```

| 接口 | 一期调用方 | 二期调用方 | 语义 |
|------|-----------|-----------|------|
| `ReserveStock` | 处方提交审核 | 诊疗模块开方 | 开方即锁定 |
| `DispenseAndReduceStock` | 发药确认 | 诊疗模块发药 | 发药实扣 |
| `CancelReservation` | 退方/驳回/作废 | 诊疗模块退方 | 释放库存 |
| `GetDrugAvailability` | 药品详情页 | 诊疗模块开方辅助 | 查询可用库存 |

## §5 处方/医嘱接口预留

处方对象一期即按二期能力完整定义字段，二期只需换 `source` 与自动填充：

| 字段 | 一期 | 二期 |
|------|------|------|
| `source` | `manual`（药房手工录入） | `outpatient / inpatient / refill`（门诊/住院/出院带药） |
| `patient_id` | `NULL`（仅存姓名/卡号） | 关联 `patients.id` |
| `diagnosis` | 自由文本 | 结构化诊断（预留 `diagnosis_code` 字段，ICD 编码） |
| `department` / `doctor_name` | 手填 | 由诊疗模块自动传入 |
| `prescription_type` | 药房选择 | 由开方场景推导 |

**二期新增表（预告）**：`patients`、`visits`、`charges`、`charge_items`、`medical_records`。

## §6 接入时序示例（二期医生开方 → 药房发药）

```
医生端（诊疗模块）                         药房端（一期 Service）
─────────────────                        ─────────────────────
1. 开方
   GET GetDrugAvailability(drugID)  ──►  返回各库可用量（辅助选药）
2. 开方保存（患者档案已建）
   prescription.source=outpatient
   prescription.patient_id=xxx
   POST /api/v1/prescriptions   ────►   创建处方
   （自动触发 ReserveStock 预占）          InventoryService.ReserveStock
3. 药房调配 / 发药
                                         按 FEFO 分配 → confirm-dispense
                                         InventoryService.DispenseAndReduceStock
4. 退方（医生撤销）
   prescription.cancel                 →  InventoryService.CancelReservation
5. 收费
                                         二期 IPricingService.CalculateBill
                                         （药费 + 挂号费 + 诊疗费合并结算）
```

## §8 药房物品 vs 临床诊疗项目（架构边界，v1.2）

### 8.1 药房管理的物品（`drugs` 表）

| 类型 | `item_type` | 示例 | 库存管理 |
|------|------------|------|---------|
| 药品 | `drug` | 阿莫西林、布洛芬 | 批号+效期+FEFO+拆零+配伍检测 |
| 耗材 | `consumable` | 注射器、纱布、手套 | 批号+效期+FEFO（同药品，无配伍检测） |

两类物品统一走进销存（采购→入库→调拨→盘点→预警）。

### 8.2 临床诊疗项目（`clinical_services` 表，v1.2 新增）

不入药房库存，独立计价，护士/医生可直接录入计费：

| 分类 | 示例 | 计价 |
|------|------|------|
| 手法治疗 | 手法复位、推拿 | 按次 |
| 注射操作 | 静脉注射、肌肉注射 | 按次 |
| 检查项目 | 心电图、血糖检测 | 按次 |

### 8.3 计费 vs 领用（v1.2）

| 场景 | 接口 | 说明 |
|------|------|------|
| **计费** | `POST /charge-records` | 药品/耗材/诊疗项目向患者收费 |
| **领用** | `POST /inventory/requisition` | 医护内部消耗（手套/纱布），不计费，仅减库存 |

### 8.4 二期合并结算

```
临床诊疗项目（clinical_services）  +  药房物品（drugs）
         ↓                              ↓
         └── IPricingService.CalculateBill() ──┘
                         ↓
                 合并费用单（charges）
```
