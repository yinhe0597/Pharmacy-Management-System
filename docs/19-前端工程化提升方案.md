# 19 前端工程化提升方案（建议评估与融合）

> 针对前端工程 5 项提升建议的评估结论与落地计划。

## 一、逐项评估

| # | 建议 | 现状 | 结论 |
|---|------|------|------|
| 1 | ESLint + Prettier | 仅 TS strict（vue-tsc），无 lint/格式化 | ✅ **融合**：ESLint 9 flat config + Prettier，lint/format 脚本 |
| 2 | Axios 封装：注入 JWT/统一错误/请求取消 | 已注入 JWT、已统一错误(401/500)；**缺请求取消** | 🟡 **补请求取消**（路由切换 abort 未完成请求） |
| 3 | 路由懒加载 + 权限守卫 | 已懒加载(`()=>import`)；已 beforeEach 角色守卫 | ✅ 已具备（静态路由 + 守卫；动态路由暂不引入，见 §三） |
| 4 | 环境变量配置 | vite.config 硬编码代理；无 .env | ✅ **融合**：`.env.development`/`.env.production` + `VITE_API_BASE_URL` |
| 5 | 类型共享（Go 后端自动生成 TS） | 手写 `types/entities.ts` | ✅ **融合**：openapi-typescript 从 `docs/swagger.json` 生成 `types/generated/api.d.ts` |

## 二、落地细节

### 2.1 ESLint + Prettier
- 依赖：`eslint` + `typescript-eslint` + `eslint-plugin-vue` + `eslint-config-prettier` + `prettier`。
- 配置：`eslint.config.js`（flat config）+ `.prettierrc`。
- 脚本：`lint`（eslint .）、`format`（prettier --write）、`format:check`。
- 说明：未采用 `@antfu/eslint-config`（风格约束强、依赖较重），采用等价的标准组合，规则贴近
  （no-unused-vars、vue 推荐规则、prettier 收尾）；`no-explicit-any` 放宽（API 层返回 `any`）。

### 2.2 Axios 请求取消
- `api/http.ts` 内置 AbortController 池：请求发起登记、完成/失败移除；导出 `cancelAllRequests()`。
- 路由 `beforeEach` 中调用 `cancelAllRequests()`，路由切换即取消未完成请求，避免旧请求覆盖新页面数据。

### 2.3 环境变量
- `.env.development`：`VITE_API_BASE_URL=/api/v1`（走 Vite 代理）。
- `.env.production`：`VITE_API_BASE_URL=/api/v1`（同源 Nginx 反代；分离部署时改为完整 URL + 后端 CORS）。
- `http.ts` 读取 `import.meta.env.VITE_API_BASE_URL`。

### 2.4 类型共享
- `openapi-typescript` 从 `../docs/swagger.json` 生成 `src/types/generated/api.d.ts`。
- 生成物作为契约权威，组件逐步由手写 `entities.ts` 迁移到生成类型（后端接口变更时重新生成）。

## 三、暂不引入（说明理由）

- **动态路由（角色 addRoute）**：当前「静态全量路由 + beforeEach 角色守卫 + 菜单权限过滤」已满足
  8 角色菜单/按钮控制，且实现简单、可静态审计；动态路由在角色数量少、权限点有限时收益不大，
  待二期诊疗模块路由膨胀时再评估。
- **@antfu/eslint-config**：风格强约束会导致现有代码大范围改动；先用标准组合沉淀，后续可按需切换。

## 四、验证
- `npm run lint` / `npm run format:check` / `npm run type-check` / `npm run build` 全绿。
- 后端接口变更后：`npm run gen:types` 重新生成类型。
