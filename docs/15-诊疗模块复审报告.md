# 15 诊疗模块复审报告

> 复审对象：患者档案（patients/patient_allergies）、处方患者字段（patient_id/is_pregnant/is_lactating/diagnosis）、
> 诊疗项目（clinical_services）、计费闭环（charge_records/from-prescription/退药冲正）、
> 交互引擎患者级检查（年龄 3008/妊娠 3009/过敏 3010/哺乳 3011）、ICD-10 参考数据、port 计价契约。
> 复审目的：为**后续修改**与**前端页面搭建**提供依据。
> 方式：逐文件阅读 + 迁移 DDL 核对 + 接口/契约对照。
>
> **修复状态：本节列出的全部问题已按「五、修改建议优先级」修复（迁移 `000025`），详见 CHANGELOG [Unreleased]。**

---

## 一、复审结论

- **已具备**：患者档案 CRUD、过敏史 CRUD、处方关联患者（patient_id/is_lactating）、
  审核自动带入过敏史（3010）与哺乳期慎用（3011）、诊疗项目目录 CRUD、计费记录（手工 + 从处方生成 + 退药冲正）、
  ICD-10 诊断编码搜索 API。
- **发现 3 个 HIGH 级问题**（处方/患者修改时布尔字段无法清除、处方计费 RefID 契约漂移、退药冲正与退药非原子）、
  **6 个 MEDIUM**（筛选接口未暴露、诊断无结构化编码、错误映射、计费筛选缺失、隐私接口开放、计费无红冲）与若干 LOW。
- **对前端的最大影响**：处方/计费/患者列表的**查询维度不全**（不能按患者/类型/日期筛选）、
  **诊断无法结构化回填**（ICD 编码不留存）、**改处方时妊娠/哺乳标记可能无法取消**（误报禁忌）。

## 二、功能配套现状

### 2.1 已具备（前端可直接对接）

| 能力 | 接口 | 备注 |
|------|------|------|
| 患者建档/查询/更新 | `POST/GET/PUT /patients`、`GET /patients/{id}` | card_no 唯一 |
| 过敏史 CRUD | `GET/POST /patients/{id}/allergies`、`DELETE /patient-allergies/{id}` | severity 1-3 |
| 处方关联患者 | `POST /prescriptions`（`patient_id`、`is_lactating`） | 审核自动过敏/哺乳检查 |
| 诊疗项目目录 | `/clinical-services` CRUD | 不入药房库存 |
| 计费 | `POST/GET /charge-records`、`POST /charge-records/from-prescription/{id}` | 从发药处方一键计费（幂等） |
| 退药冲正 | 随 `POST /prescriptions/{id}/return` 自动写负金额计费 | 非原子，见 §3.3 |
| ICD-10 搜索 | `GET /reference/diagnosis-codes?keyword=` | 名称/编码/拼音码 |
| 目录匹配 | `GET /reference/drug-match?name=` | 医保类别/集采批次 |

### 2.2 功能缺口（前端搭建需补/绕行）

| # | 缺口 | 现状 | 影响 |
|---|------|------|------|
| G1 | **处方列表不能按患者/类型筛选** | repo `PrescriptionFilter` 支持 `PatientID/PrescriptionType`，handler List 只暴露 `status/patient_name/start/end` | 前端做不了「患者历史处方」「按麻精类型筛选」 |
| G2 | **诊断无结构化编码** | `prescriptions.diagnosis` 为自由文本，无 `diagnosis_code` 字段（docs/05 §5 承诺预留但未落） | ICD-10 搜索 API 与处方录入脱节，无法统计病种 |
| G3 | **患者信息不自动回填** | 处方患者姓名/性别/年龄/卡号/哺乳标记均需手工录入，与 `patients` 表无回填/校验 | 同一患者多次开方重复录入，易与档案不一致 |
| G4 | **计费列表无筛选** | `GET /charge-records` 仅 keyword，无 ref_type/ref_id/日期/类型筛选 | 前端账单页/处方对账无法按来源定位 |
| G5 | **计费无红冲/作废** | 手工录错计费无法作废（退药冲正只覆盖处方退药） | 账务纠错依赖补录负数，体验差 |
| G6 | **无「按患者看费用/处方」聚合视图** | 无按 patient_id 汇总计费、无患者就诊历史端点 | 二期 `visits` 未落地前的替代手段缺失 |
| G7 | **诊疗项目无启停用** | `clinical_services.status` 字段存在但无切换端点 | 下架项目只能硬删（有下游引用时失败） |

## 三、代码问题（按严重度）

### 3.1 HIGH

**H1 · 处方修改时布尔字段无法清除（GORM 零值跳过）**
- 位置：`prescription_repo.go UpdateBase` → `Model(p).Omit(...).Updates(p)`；GORM 结构体更新**跳过零值字段**。
- 影响：`Update` 处方时 `is_pregnant`/`is_lactating` 由 true 改为 false **不落库**——患者已非孕期但仍触发妊娠禁忌（3009）误报；`patient_age`/`patient_card_no` 等清空也不生效。
- 修复：`UpdateBase` 改 `Select("*")` 全量更新（调用方已重建完整对象），或对布尔字段用 `Updates(map)`。

**H2 · 计价契约 RefID 漂移**
- 位置：`pricing/simple_pricing_service.go CalculatePrescriptionAmount` 中 `RefID: it.ID`（处方明细 ID）。
- 契约：docs/05 §4 `PriceLine.RefID` 定义为「药品= drug_id；诊疗费=收费项目ID」。
- 影响：前端按 `RefID` 关联药品会取到明细 ID，查询药品失败；契约测试只断言行数/金额，未覆盖 RefID 语义。
- 修复：`RefID` 改为药品 `DrugID`（如需明细可加 `ItemID` 字段），同步更新契约测试。

**H3 · 退药冲正与退药非同一事务**
- 位置：`prescription_handler.go Return` 先 `svc.Return(...)` 成功，再 `clinical.RefundPrescription(...)`。
- 影响：冲正写库失败时退药已提交 → 账实不一致（药已退、款未冲），且无重试入口/幂等提示。
- 修复（择一）：A）将冲正并入 `Return` 事务（需向 PrescriptionService 注入 ClinicalService 并透传 tx）；
  B）冲正失败返回明确错误码 + 前端提供「补冲正」按钮（`POST /charge-records/refund` 幂等）。

### 3.2 MEDIUM

**M1 · 患者档案/过敏史错误映射**
- `patient_service.go`：`GetDetail`/`Update` 中 `gorm.ErrRecordNotFound` 直接上抛 → handler 统一映射为 **500**（应为 404）；
  `Create` 重复 card_no 触发唯一约束 → 原始 DB 错误（应为 409 友好提示）。
- `clinical_service.go CreateService`：重复 code 同理（应为 409）。

**M2 · 处方列表接口未暴露筛选维度（同 G1）**
- `prescription_handler.go List` 未绑定 `patient_id`/`prescription_type`（repo 已支持）。前端需在后端补参数或改走特殊药品列表接口。

**M3 · 计费 GET 与患者档案 GET 权限过宽**
- `charge-records`、`/patients/{id}`、`/patients/{id}/allergies` 挂在 `Authed`（任意登录用户）。
- 计费与患者卡号/电话属敏感信息；建议计费查看收窄到 `ReportAccess`∪药学人员，患者档案收窄到 Clinical/Pharmacy。

**M4 · 手工计费输入校验不足**
- `ChargeInput.UnitPrice binding:"required"` → 0 元免费项被拒；`Quantity<=0` 一律置 1（**负数也被吞成 1**，应拒绝）；
  `ItemType` 无枚举校验；drug 类型不校验药品存在/启停用。
- 影响：前端录入错误静默纠正（负数量→1），账务与用户预期不符。

**M5 · 患者/过敏史字段校验**
- `PatientService.Update` 零值跳过（同 H1，清空 phone/gender、`is_lactating` true→false 不生效）；
- `AddAllergy` 的 `severity > 3` 未限制（默认 1，可传 99）。

**M6 · 处方详情缺少患者档案联动**
- `GET /prescriptions/{id}` 返回处方快照（姓名/年龄等），不返回关联 `patients` 档案与过敏史；
  前端开方页需患者过敏史需另发请求，且无法校验快照与档案是否一致。

### 3.3 LOW

- **L1**：`RefundPrescription` 冲正记录 `UnitPrice=it.UnitPrice`、`Amount=-混合金额`，混合口径下 `qty×price≠|amount|`，前端若按行单价×数量合计会不一致（应以 `amount` 为准）。
- **L2**：`prescriptions.patient_id` 无外键约束（000001 为裸 BIGINT，000020 未补 FK）；将来删除患者无级联保护。
- **L3**：`ChargePrescription` 不校验处方状态——未发药处方调用返回空列表且无提示（应校验 `status=dispensed` 并返回 409）。
- **L4**：交互引擎年龄解析取 `PatientAge` 前导数字（"新生儿"→0 不检查；"1岁2个月"→1），边界可接受但建议结构化。
- **L5**：`port.Patient` 无 `IsLactating` 字段（患者档案哺乳标记仅存在 model 层，port 契约不透出）；开方时哺乳标记依赖前端手工传 `is_lactating`，与档案可能不一致。
- **L6**：`GetMedicationHistory` 恒返回空（二期），重复用药分析暂无数据源。

## 四、前端搭建参考

### 4.1 主流程数据流（推荐顺序）

```
患者建档(POST /patients) ──▶ 开方(POST /prescriptions, 带 patient_id/is_lactating)
        │                             │
        │ 审核自动检查                │ 过敏史(3010)/哺乳(3011)/妊娠(3009)/年龄(3008)/配伍/极量/重复用药
        ▼                             ▼
  过敏史维护 ──────────────▶ 审核(药师 pass/reject/return) → 调配 → 发药确认(双人)
                                          │
                                          ▼
                              计费(POST /charge-records/from-prescription/:id)
                                          │
                                          ▼
                              退药(自动冲正负计费)
```

### 4.2 前端表单字段（处方录入）

| 字段 | 来源 | 说明 |
|------|------|------|
| `patient_id` | 患者档案选择 | 建议前端用 `GET /patients?keyword=` 搜索后选中 |
| `patient_name/gender/age/card_no` | 快照（可回填） | 后端暂不回填，前端可自行填充 |
| `is_pregnant` / `is_lactating` | 表单开关 | ⚠️ 后端 H1 修复前，改 false 不生效 |
| `diagnosis` | 自由文本 + ICD-10 搜索 | 可调 `GET /reference/diagnosis-codes` 辅助，但编码不落库（G2） |
| `department/doctor_name/prescription_type` | 表单 | — |

### 4.3 需要后端先行补齐的接口（前端落地前提）

1. `GET /prescriptions?patient_id=&prescription_type=`（repo 已支持，暴露参数即可）
2. 处方/患者修改布尔字段持久化修复（H1）——否则孕期取消功能不可用
3. `GET /charge-records?ref_type=&ref_id=&start=&end=` 筛选
4. 计费红冲（通用负计费或作废端点）
5. 患者档案错误码映射（404/409）——前端统一错误提示
6. （可选）处方详情聚合患者档案 + 过敏史（M6）

### 4.4 页面清单建议

| 页面 | 依赖接口 | 阻塞项 |
|------|---------|--------|
| 患者管理（列表/详情/过敏史） | `/patients*` | 无 |
| 开方（含患者搜索/诊断补全） | `/patients`、`/reference/diagnosis-codes`、`/drugs`、`/prescriptions` | G2（诊断编码不落库，先自由文本） |
| 处方列表（按患者/类型/状态筛选） | `GET /prescriptions` | M2（补筛选参数） |
| 处方详情（状态时间线/发药/计费） | `GET /prescriptions/{id}` | 无 |
| 计费/账单（按处方/日期/类型） | `GET /charge-records` | G4（补筛选） |
| 诊疗项目目录 | `/clinical-services` | G7（补启停用） |
| 报表（含患者费用汇总） | `/reports/*` | G6（无按患者汇总端点） |
