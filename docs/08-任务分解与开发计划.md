# 08 任务分解与开发计划

> 12 周计划，面向「纯后端 API + Swagger」交付形态。
> 每个任务含交付物与验收标准；以里程碑（M0–M6）为节奏节点。

---

## 一、里程碑总览

| 里程碑 | 时间 | 内容 | 验收要点 |
|--------|------|------|---------|
| M0 | 第0-1周末 | 可运行骨架 + Swagger | 服务启动、迁移成功、登录可用、文档可浏览 |
| M1 | 第3周末 | 药品/供应商 API | CRUD 完整、一药多规/一品多商、启停用、冻结规则 |
| M2 | 第6周末 | 库存闭环 | 入库/调拨/拆零/预占释放/预警/盘点/采购，并发正确 |
| M3 | 第8周末 | 处方全链路 | 录入→审核→调配→发药→退药，状态机与批次可追溯 |
| M4 | 第9周末 | 特殊药品 + 药学服务 | 五专流程、空安瓿回收、咨询/不良反应/指导 |
| M5 | 第11周末 | 报表 + 契约测试 | 4 类报表、预留接口契约通过 |
| M6 | 第12周末 | 一期交付 | 全流程测试通过、文档齐全、部署文档可用 |

## 二、周级任务分解

### 第0周 环境与脚手架
- [ ] Go 项目初始化（`go mod init`），Git 仓库建立
- [ ] PostgreSQL 本地环境（Docker 或本机安装）+ `yaofang` 数据库
- [ ] golang-migrate 接入；`000001_init.up.sql` / `.down.sql` 初稿落库
- [ ] Gin 骨架：路由注册、`{code,message,data}` 响应封装、错误类型 `pkg/errs`
- [ ] 中间件：RequestID / slog 日志 / Recover / JWT
- [ ] 配置：Viper + `configs/config.yaml`，环境变量覆盖
- [ ] swaggo 接入，`/swagger/index.html` 可访问
- [ ] `pkg/money`（分）与 `domain/enum` 基础类型
- 验收：`go run ./cmd/server` 启动，`/healthz` 返回 ok，`/swagger` 可浏览

### 第1周 基础设施与数据模型
- [ ] 全部 GORM 模型（对应 02 文档 §2 表 1-27）
- [ ] 用户/鉴权模块：`AuthService`、`users` CRUD、角色、bcrypt、JWT 签发与解析
- [ ] `pkg/pagination`、通用筛选解析
- [ ] 种子数据 `000002_seed`：分类、库房、默认管理员
- [ ] CI 脚本：lint + unit test 门槛
- 验收：登录/鉴权全通；数据模型与迁移一致（`gorm.AutoMigrate` 校验与 SQL 对齐）

### 第2-3周 药品主数据 + 供应商
- [ ] `DrugService`：CRUD、启停用、冻结规则、一药多规/一品多商唯一性
- [ ] 分类管理 `drug_categories`
- [ ] 配伍禁忌 `drug_interactions` 维护与查询
- [ ] `SupplierService`：供应商 CRUD、`drug_suppliers` 供货关系、默认供货商
- [ ] 单元测试：主数据规则、冻结、唯一约束
- 验收（M1）：药品/供应商接口全绿，Swagger 含全部注解

### 第4周 库存基础
- [ ] `InventoryService`：库房管理、入库（含采购收货批次绑定）、调拨、拆零、报损调整
- [ ] 流水 `inventory_transactions` 全部写入（前后数量、单据号）
- [ ] 库存查询（多条件）+ 流水查询
- 验收：入库→调拨→拆零→调整 全链路手工测试通过

### 第5周 库存高级（并发正确性）
- [ ] 预占/释放/实扣（行锁 + 条件更新 + `stock_reservations`）
- [ ] FEFO 批次选择器（domain/rule）
- [ ] 效期预警 + 过期锁定定时任务；`stock_alerts`
- [ ] 上下限预警 + 采购计划建议
- [ ] 盘点（周期/动态、按批号、差异调整、进行中禁止变动）
- [ ] 单元 + 集成测试：并发预占/实扣、退方释放（见 07 §2.1、§3.1）
- 验收（M2）：并发测试不超卖、无负库存；预警任务正确

### 第6周 采购模块
- [ ] `PurchaseService`：采购计划建议、采购单、收货（批次/效期/质检）、确认入库
- [ ] 采购单状态机（draft/submitted/partial/received/cancelled）
- 验收：采购入库→库存增加→流水正确；质检不合格不入库

### 第7-8周 处方核心
- [ ] `PrescriptionService`：录入（快照计价）、修改、提交（预占）
- [ ] 审核：配伍/极量/重复用药检查 + 审核日志
- [ ] 调配：FEFO 分配批次、可调整、库存不足拦截
- [ ] 发药确认：核销实扣、发药记录、双人核对、`dispensed` 状态
- [ ] 退药：整方/部分、按原批次回补、状态流转
- [ ] 作废：释放预占
- [ ] 处方状态机 + `prescription_audit_logs`
- [ ] 集成测试：全链路、退药恢复、并发流转（见 07 §3）
- 验收（M3）：处方从录入到退药全链路闭环，批次全程可追溯

### 第9周 特殊药品 + 药学服务
- [ ] `SpecialDrugService`：五专流程、专用处方必填校验、双人核对、处方限量
- [ ] 空安瓿回收登记与核对
- [ ] 专账 `special_drug_ledgers` 查询与统计
- [ ] `PharmaService`：用药咨询、不良反应、用药指导
- [ ] 单元测试：五专规则（见 07 §2.5）
- 验收（M4）：特殊处方发药→专账→空安瓿回收闭环；三服务 CRUD 可用

### 第10周 报表
- [ ] `ReportService`：进销存汇总（期初+入-出=期末）
- [ ] 效期分析（3/6/12 月分档、已过期）
- [ ] 特殊药品使用统计、调配工作量统计
- 验收：报表 SQL 与业务口径一致，抽样核对数值

### 第11周 契约测试 + 性能优化
- [ ] 实现 `port` 三接口并接好简易患者服务（见 05 §7）
- [ ] 契约测试：模拟诊疗模块调用（见 07 §4）
- [ ] 性能：列表接口索引核对、慢查询排查、事务长度审计
- [ ] Swagger 与接口文档对齐（`swag init` 全绿）
- 验收（M5）：契约测试全绿；接口文档无缺漏

### 第12周 测试与交付
- [ ] 全量回归（单元 + 集成 + 契约）
- [ ] Bug 修复、代码审查整改
- [ ] 部署运维文档（Windows / Linux、systemd、备份恢复）
- [ ] 测试报告 + 一期交付物打包（见 §四）
- 验收（M6）：全流程走查通过，交付物齐全

## 三、风险清单

| 风险 | 影响 | 缓解 |
|------|------|------|
| 库存并发正确性缺陷 | 超卖/负库存 | 行锁+条件更新双保险；第5周专项测试 |
| 拆零单位换算混乱 | 数量/金额错误 | 统一 LDU 口径，domain/rule 集中换算，单元测试覆盖 |
| 金额浮点误差 | 计价错误 | 一律整数分，禁浮点，`pkg/money` 统一舍入 |
| 处方状态机越权流转 | 数据不一致 | 流转仅 Service 方法触发 + 版本号 + 审计日志 |
| 二期接口契约漂移 | 二期返工 | 契约测试守门，接口文档随改动同步 |
| 麻精合规要求不清 | 业务规则偏差 | 规则常量集中配置，五专流程先评审再实现 |
| 效期预警定时任务失效 | 过期药品发出 | 双重兜底（日任务 + 发药时实时校验 status） |
