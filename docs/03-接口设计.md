# 03 接口设计

> 一期交付纯后端 REST API，Swagger（swaggo 注解）随代码生成。
> 所有接口前缀 `/api/v1`；鉴权：除登录外均需 `Authorization: Bearer <token>`。

---

## §1 通用约定

### 1.1 响应信封

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

- `code=0` 成功；非 0 为业务错误码，见 §2。
- HTTP 状态码语义：`200` 成功；`400` 参数错误；`401` 未认证；`403` 无权限；`404` 不存在；`409` 状态冲突；`500` 服务异常。
- 业务错误与 HTTP 状态码的映射在 handler 统一完成（错误码 → HTTP 状态）。

### 1.2 分页

| 参数 | 说明 |
|------|------|
| `page` | 页码，从 1 起，默认 1 |
| `page_size` | 每页条数，默认 20，最大 200 |

```json
"data": {
  "list": [],
  "total": 100,
  "page": 1,
  "page_size": 20
}
```

### 1.3 通用筛选

- 时间区间统一 `start` / `end`（RFC3339），如 `2026-08-01T00:00:00+08:00`。
- 模糊搜索统一参数 `keyword`。
- 金额字段统一为整数「分」。

### 1.4 时间与 ID

- 所有时间为 `RFC3339` 字符串；日期（效期等）为 `YYYY-MM-DD`。
- ID 为 int64。

## §2 错误码体系

| 区段 | 模块 |
|------|------|
| 9xxx | 通用（参数、鉴权、系统） |
| 1xxx | 药品/供应商 |
| 2xxx | 库存/采购 |
| 3xxx | 处方 |
| 4xxx | 特殊药品 |
| 5xxx | 药学服务/报表 |
| 6xxx | 患者/诊疗/就诊结算 |

### 用户角色体系

| 角色 | 常量 | 权限范围 |
|------|------|---------|
| 管理员 | `admin` | 全部权限（含用户管理） |
| 药房主任 | `pharmacy_director` | 药品/库存/采购/处方/特殊药品/药学服务/报表/用户管理 |
| 药师 | `pharmacist` | **必须审核处方**；可退回医生修改（释放预占，医生修改后重新提交再预占）或直接修改；药品/库存/处方/特殊药品/药学服务/报表/调配/核对 |
| 医生 | `doctor` | 处方录入/患者写/药学服务/调配/核对 |
| 跟诊护士 | `clinic_nurse` | 患者信息管理、**核对医嘱**、辅助录入医嘱/处方草稿、诊疗执行计费（无正式审核/无库存写） |
| 药房护士 | `pharmacy_nurse` | 药品/库存查询、**耗材领用/补发登记**、处方执行（调配/发药/核对辅助）、辅助核对收费、药学服务（无处方开立权/无正式审核） |
| 采购员 | `buyer` | 采购 |
| 财务 | `finance` | 报表 |

> 调配（发药）与核对（双签）职能由医生/药师兼任，不再设独立调配员/核对员角色。
>
> 原 `nurse` 角色已细化为 `clinic_nurse`（跟诊护士）与 `pharmacy_nurse`（药房护士），详见 docs/18。
>
> 种子用户（密码均为 `admin123`）：`admin` / `doctor` / `clinic_nurse` / `pharmacy_nurse` / `pharmacy_chief` / `pharmacist` / `buyer` / `finance`

## §4 Swagger 约定

- 使用 swaggo 注解，包注释处生成 `docs/swagger.*`。
- 每个 Handler 标注 `@Summary / @Description / @Param / @Success / @Failure / @Router / @Security BearerAuth`。
- 路由注册时统一 `auth` 中间件，白名单 `/api/v1/auth/login`、`/healthz`、`/readyz`、`/swagger/*`。
- **写操作按角色矩阵强制（RBAC）**：处方开立=ClinicalStaff、处方执行/库存写/药学服务/计费=PharmacyStaff、
  药品/配伍/交互规则/特殊药品目录=DrugAdmin、采购/供应商=PurchaseStaff、报表=ReportAccess、用户管理=UserAdmin；
  只读接口任意登录用户可用。
- 交付物包含 `swagger.yaml`，供前端二期直接对接。

## §5 幂等与并发提示

- **重复提交防护**：`submit`/`review`/`confirm-dispense`/`return` 依赖 `prescriptions.version` 乐观锁，
  并发操作返回 `9005 状态冲突`，由前端刷新后重试。
- **重复发药防护**：发药记录对 `(prescription_id, item_id)` 有唯一约束兜底。
- **库存并发**：同一批次多单并发发药由行锁 + 条件更新保证不超卖，冲突方返回 `2004 预占冲突`。
