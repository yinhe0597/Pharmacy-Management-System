# 03 接口设计

> 一期交付纯后端 REST API，Swagger（swaggo 注解）随代码生成。
> 所有接口前缀 `/api/v1`；鉴权：除登录外均需 `Authorization: Bearer <token>`。

---

## §1 通用约定

### 1.1 响应信封

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

- `code=0` 成功；非 0 为业务错误码，见 §2。
- HTTP 状态码语义：`200` 成功；`400` 参数错误；`401` 未认证；`403` 无权限；`404` 不存在；`409` 状态冲突；`500` 服务异常。
- 业务错误与 HTTP 状态码的映射在 handler 统一完成（错误码 → HTTP 状态）。

### 1.2 分页

| 参数 | 说明 |
|------|------|
| `page` | 页码，从 1 起，默认 1 |
| `page_size` | 每页条数，默认 20，最大 200 |

```json
"data": {
  "list": [],
  "total": 100,
  "page": 1,
  "page_size": 20
}
```

### 1.3 通用筛选

- 时间区间统一 `start` / `end`（RFC3339），如 `2026-08-01T00:00:00+08:00`。
- 模糊搜索统一参数 `keyword`。
- 金额字段统一为整数「分」。

### 1.4 时间与 ID

- 所有时间为 `RFC3339` 字符串；日期（效期等）为 `YYYY-MM-DD`。
- ID 为 int64。

## §2 错误码体系

| 区段 | 模块 |
|------|------|
| 9xxx | 通用（参数、鉴权、系统） |
| 1xxx | 药品/供应商 |
| 2xxx | 库存/采购 |
| 3xxx | 处方 |
| 4xxx | 特殊药品 |
| 5xxx | 药学服务/报表 |

### 用户角色体系

| 角色 | 常量 | 权限范围 |
|------|------|---------|
| 管理员 | `admin` | 全部权限（含用户管理） |
| 药房主任 | `pharmacy_director` | 药品/库存/采购/处方/特殊药品/药学服务/报表/用户管理 |
| 药师 | `pharmacist` | 药品/库存/处方/特殊药品/药学服务/报表 |
| 医生 | `doctor` | 处方录入/药学服务（临床端） |
| 护士 | `nurse` | 处方录入/药学服务（临床端） |
| 调配员 | `dispenser` | 库存/处方调配 |
| 核对员 | `checker` | 库存/处方核对/特殊药品核对 |
| 采购员 | `buyer` | 采购 |
| 财务 | `finance` | 报表 |

> 种子用户（密码均为 `admin123`）：`admin` / `doctor` / `nurse` / `pharmacy_chief` / `pharmacist` / `dispenser` / `checker` / `buyer` / `finance`

常见错误码（完整清单以 `pkg/errs` 为准）：

| 码 | 含义 |
|----|------|
| 0 | 成功 |
| 9001 | 参数错误 |

| 9003 | 无权限 |

| 3001 | 处方状态不允许该操作 |
| 3002 | 极量超限 |
| 3003 | 配伍禁忌 |

| 3005 | 批次分配不足 |
| 3006 | 处方明细不存在 |
| 3007 | 退药数量超过已发数量 |

### 3.6 处方 prescriptions（核心）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/prescriptions` | 手工录入（draft，含预检） |
| PUT | `/api/v1/prescriptions/{id}` | 修改（仅 pending_review） |
| POST | `/api/v1/prescriptions/{id}/submit` | 提交审核（执行库存预占） |

| POST | `/api/v1/prescriptions/{id}/dispense` | 调配（按 FEFO 分配批次，可调整） |
| POST | `/api/v1/prescriptions/{id}/confirm-dispense` | 发药确认（实扣库存，记录发药人） |

```jsonc

{
  "patient_name": "张三",
  "patient_gender": "男",
  "patient_age": "35岁",
  "patient_card_no": "",
  "diagnosis": "上呼吸道感染",
  "department": "内科",
  "doctor_name": "李医生",
  "prescription_type": 0,
  "items": [
    {
      "drug_id": 101,
      "quantity": 12,              // 拆零单位（粒）
      "usage_text": "口服",
      "frequency": "tid",
      "single_dose": 1,
      "days": 4,
      "is_split": true
    }
  ]
}
// 服务端：载入药品快照 → 计算单价/金额 → 创建 draft
```

```jsonc
// POST /api/v1/prescriptions/{id}/review
{ "action": "pass", "remarks": "" }        // pass/reject
// pass → 校验通过才允许；内部完成配伍/极量/重复用药检查，违规返回对应错误码
```

```jsonc
// POST /api/v1/prescriptions/{id}/confirm-dispense
{ "checker_id": 5 }
// 事务：锁库存行 → 逐条核销预占/实扣 → 写流水(dispense) → 记录发药记录 → 处方状态=dispensed
// 特殊处方同时写 special_drug_ledgers
```

```jsonc
// POST /api/v1/prescriptions/{id}/return
{
  "items": [
    { "item_id": 301, "return_quantity": 6 }   // 部分退；整方退则全量
  ],
  "reason": "患者退药"
}
// 事务：按 dispense_records 原批次回补 → 写流水(dispense_return) → 更新 item/prescription 状态
```

## §4 Swagger 约定

- 使用 swaggo 注解，包注释处生成 `docs/swagger.*`。
- 每个 Handler 标注 `@Summary / @Description / @Param / @Success / @Failure / @Router / @Security BearerAuth`。
- 路由注册时统一 `auth` 中间件，白名单 `/api/v1/auth/login`、`/healthz`、`/readyz`、`/swagger/*`。
- 交付物包含 `swagger.yaml`，供前端二期直接对接。

## §5 幂等与并发提示

- **重复提交防护**：`submit`/`review`/`confirm-dispense`/`return` 依赖 `prescriptions.version` 乐观锁，
  并发操作返回 `9005 状态冲突`，由前端刷新后重试。
- **重复发药防护**：发药记录对 `(prescription_id, item_id)` 有唯一约束兜底。
- **库存并发**：同一批次多单并发发药由行锁 + 条件更新保证不超卖，冲突方返回 `2004 预占冲突`。
