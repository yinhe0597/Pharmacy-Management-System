# 17 前端开发指南与进度规划

> 依据：后端代码结构与路由矩阵（`internal/handler/*` + `internal/server/server.go`）、
> 接口契约（docs/03、docs/16）、功能定位（药房进销存 + 处方调配，7 角色，二期诊疗扩展）。
> 目标读者：前端开发团队；本文是前端工程的**设计基线**与**实施计划**。

## 一、项目定位与前端形态

### 1.1 后端能力地图（前端域映射）

| 后端模块（Service/Handler） | 前端域 | 说明 |
|---------------------------|--------|------|
| auth / users / operation_logs | 系统域 | 登录、用户管理、操作日志 |
| drugs / categories / interactions(成分/分类/标签) | 主数据域 | 药品/分类/配伍/交互规则 |
| suppliers / purchase | 采购域 | 供应商、采购单、收货质检 |
| inventory（库存/调拨/拆零/盘点/预警/领用） | 库存域 | 含拆零操作单 |
| prescriptions | 处方域 | 状态机全流程 |
| patients / patient_allergies | 患者域 | 档案与过敏史 |
| charge_records / clinical_services | 计费域 | 诊疗项目目录、计费/红冲 |
| specialdrug（五专/空安瓿/专账） | 特殊药品域 | 合规流程 |
| pharmaservice（咨询/不良反应/指导） | 药学服务域 | 三服务 CRUD |
| reports（6 类报表） | 报表域 | 进销存/效期/特殊/工作量/拆零/患者费用 |
| reference（ICD-10/集采/医保/耗材/非医保） | 参考数据域 | 只读检索 + 目录匹配 |

### 1.2 前端形态定位

- **形态**：纯前端 SPA（中后台管理系统），与后端完全分离部署；开发期走 Vite 代理或 CORS（后端已支持）。
- **用户**：7 种角色（admin / pharmacy_director / pharmacist / doctor / nurse / buyer / finance），
  菜单与按钮按角色收敛。
- **核心闭环**：建档 → 开方 → 审核 → 调配 → 发药（双人）→ 计费 → 退药（冲正）→ 报表。
- **二期扩展**：新增就诊/病历页面，开方从「手工录入」演进为「医生端开立」，前端路由/组件预留扩展位。

## 二、技术选型

| 层 | 推荐 | 备选 | 理由 |
|----|------|------|------|
| 构建 | **Vite 5+** | webpack | 启动快、TS 一等公民 |
| 框架 | **Vue 3（组合式 API + `<script setup>`）** | React 18 | 中后台生态成熟、上手快、与中文团队协作成本低 |
| 语言 | **TypeScript（strict）** | — | 对接 swagger 契约，减少联调缺陷 |
| UI 组件库 | **Element Plus** | Ant Design Vue | 表格/表单/树/对话框齐全，药房表单密集型场景友好 |
| 状态 | **Pinia** | Vuex | TS 友好、模块化 |
| 路由 | **Vue Router 4** | — | 动态路由按角色注册 |
| 请求 | **Axios**（拦截器封装） | fetch | 统一信封/错误/401 处理 |
| 类型生成 | **openapi-typescript**（基于 `docs/swagger.json`） | 手写 types | 与后端契约同步 |
| 代码规范 | **ESLint + Prettier + husky** | — | 与后端 golangci-lint 同等门槛 |
| 图表（报表） | **ECharts** | — | 进销存趋势/效期分档可视化 |
| Mock | 不启用（后端已就绪+种子数据） | vite-plugin-mock | 直接联调，减少双维护 |

## 三、前端工程结构

```
pharmacy-web/
├── src/
│   ├── api/                      # 📦 按后端模块一一对应的接口层
│   │   ├── auth.ts  drugs.ts  suppliers.ts  purchase.ts
│   │   ├── inventory.ts  prescriptions.ts  patients.ts  billing.ts
│   │   ├── clinical.ts  special.ts  pharma.ts  reports.ts  reference.ts
│   │   └── http.ts               # Axios 实例（信封解包/错误映射/401 跳转）
│   ├── types/                    # 📐 契约类型（swagger 生成 + 手工补充）
│   │   ├── generated/            # openapi-typescript 产物（勿手改）
│   │   └── business.ts           # 业务枚举/状态机/常量（与后端 enum 对齐）
│   ├── stores/                   # 🗃️ Pinia：user（token/角色/权限点）、app（菜单/标签页）
│   ├── router/                   # 🛣️ 路由表 + 守卫（登录/角色/动态菜单）
│   ├── directives/               # 🛡️ v-permission（按钮级角色控制）
│   ├── layouts/                  # 🖼️ 主布局：侧边菜单/顶栏/多标签页
│   ├── views/                    # 📄 页面（按域分组，见 §五）
│   │   ├── login/ dashboard/ admin/
│   │   ├── patients/ prescriptions/ dispensing/ billing/
│   │   ├── drugs/ inventory/ purchase/ special/ pharma/
│   │   ├── clinical/ reference/ reports/
│   ├── components/               # 🧩 通用组件（见 §六）
│   ├── composables/              # 🔧 组合函数（usePagination/useDict/usePermission）
│   ├── utils/                    # 🧰 money(分) / format(RFC3339,日期) / auth / download
│   └── styles/
├── vite.config.ts                # 代理 /api → http://localhost:8080
├── .env.development / .env.production
└── package.json
```

**分层纪律**（与后端四层对应）：
- `views` 只做组合与交互，不直接写请求 → 一律走 `api/` 层；
- `api/` 只负责 HTTP 与信封解包，返回业务数据（`data` 字段），不做业务判断；
- 状态机/枚举常量集中在 `types/business.ts`，与后端 `domain/enum` 对齐，双端同源维护。

## 四、基础设施设计

### 4.1 请求层（`api/http.ts`）

```ts
// 统一信封 { code, message, data }
// 拦截器：
//   请求：注入 Authorization: Bearer <token>
//   响应：code===0 → 返回 data；否则按 code 映射提示（9002→登录页，9003→无权限，9005→刷新重试）
//   网络错误/超时 → 统一 toast
```

### 4.2 错误码提示映射（与 `pkg/errs` 对齐）

| 段 | 前端处理 |
|----|---------|
| 9002/9003 | 跳登录 / 提示无权限 |
| 9005、2004、3001 | 「状态冲突，请刷新后重试」 |
| 3003/3008-3011 | 处方审核拦截项，开方页红色警示 + 交互检测结果面板 |
| 2013/4003 | 麻精双人复核缺失提示（调配/发药/拆零场景） |
| 6xxx | 患者/诊疗业务提示（404/409 直接展示 message） |

### 4.3 鉴权与 RBAC

- `stores/user`：登录后存 token + 用户（id/name/role）；刷新后 `GET /auth/profile` 恢复。
- 路由守卫：未登录 → `/login`；已登录按角色过滤菜单（见 §五角色列）。
- 按钮级：`v-permission="'drug:create'"` 指令，权限点与后端路由组对应
  （Authed=登录可见，Pharmacy/Clinical/DrugAdmin/Purchase/Report/Billing/UserAdmin 映射为权限点）。

### 4.4 金额与时间（硬性约定）

- 金额一律后端「分」→ 前端 `utils/money.ts`：`formatCents(1200) → ¥12.00`；合计用整数分计算，展示层再格式化。
- 冲正/红冲行 `amount<0` 红色展示；`voided=true` 原单置灰。
- 时间：接口出入参 RFC3339；日期组件统一 `YYYY-MM-DD`；列表时间显示本地化。

### 4.5 处方状态机驱动的操作面板

| 状态 | 可用操作 |
|------|---------|
| pending_review | 修改 / 提交审核 / 作废 |
| reviewed_passed | 调配 / 作废 |
| dispensing | 发药确认（核对=当前用户，麻精强制双人）/ 作废 |
| dispensed | 退药 / 一键计费 |
| reviewed_rejected / returned / cancelled | 只读（驳回可修改重提） |

> 前端只按状态渲染按钮，后端仍做最终校验（状态机唯一事实来源在后端）。

## 五、页面与功能规划（按域）

### 5.1 系统域
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 登录 | 全部 | 账号密码 → JWT；错误提示 |
| 工作台 Dashboard | 全部 | 今日处方/预警/库存概览（轮询预警接口） |
| 用户管理 | admin、pharmacy_director | 用户 CRUD、角色分配、启停用 |
| 操作日志 | admin、pharmacy_director | 按用户/动作/资源检索 |

### 5.2 主数据域
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 药品管理 | 写:DrugAdmin；查:登录 | 列表（keyword/分类/抗生素/管制/医保类别筛选）；表单含**目录匹配标注**（`/reference/drug-match` 自动带出甲乙类/集采批次）、拆零参数、临床字段（妊娠分级/年龄限制/交互标签） |
| 分类管理 | 写:DrugAdmin | 树形分类 |
| 配伍/交互规则 | 写:DrugAdmin | 显式/成分/分类/标签四类规则 CRUD；证据等级 |
| 供应商管理 | 写:Purchase；查:登录 | 供应商 + 药品供货关系 |

### 5.3 采购域
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 采购建议 | Purchase | 基于上下限+消耗的建议量 → 一键生成采购单 |
| 采购单 | Purchase | 状态机（草稿→提交→收货→入库→作废）；收货录入批次/效期/质检 |
| 收货单 | Purchase | 质检不合格标记、确认入库 |

### 5.4 库存域
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 库存列表 | 查:登录 | 按药品/库房/批号/状态筛选；LDU 折算展示；近效期标色 |
| 库房管理 | 写:UserAdmin | 库房 CRUD |
| 调拨/入库/领用/报损 | Pharmacy | 双库房调拨、其他入库、领用出库、调整（填原因） |
| 拆零 | Pharmacy | 按盒/按片拆零（零头+破损平齐校验）；**麻精须录入复核人** |
| 拆零操作单 | 查:登录 | 操作人/复核人审计列表 |
| 盘点 | Pharmacy | 建单→录入实盘→差异调整→完成；进行中禁出入库提示 |
| 预警中心 | Pharmacy | 效期/过期/下限三类；处理（resolved/ignored）留痕 |

### 5.5 患者域
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 患者管理 | 写:Clinical；查:Pharmacy | 档案 CRUD（卡号唯一）；过敏史管理（severity 1-3） |
| 患者详情 | Pharmacy | 档案 + 过敏史 + **费用聚合**（`/reports/patient-charges`）+ 处方历史（`/prescriptions?patient_id=`） |

### 5.6 处方域（核心）
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 开方 | Clinical | 患者搜索选择（**自动回填**姓名/性别/年龄/卡号/哺乳）；**ICD-10 诊断补全**（`/reference/diagnosis-codes`）存 `diagnosis_code`；药品搜索（医保/集采标注）；明细行：剂量/频次/天数/是否拆零/用量；`is_pregnant`/`is_lactating` 开关；**交互检查实时面板**（过敏 3010/哺乳 3011/妊娠 3009/配伍/极量/重复用药）；麻精必填卡号+诊断+限量提示 |
| 处方列表 | 查:登录 | 状态/患者/类型/日期筛选（`patient_id`、`prescription_type`） |
| 处方详情 | Pharmacy | 状态时间线（audit_logs）、明细、**发药批次记录**、患者档案+过敏史聚合、计费状态 |
| 审核 | pharmacist/director/admin | pass/reject/return 三动作；拦截项展示；警告项确认 |
| 调配/发药 | Pharmacy | 调配（FEFO 分配）；发药确认（**核对人=当前用户**，麻精双人分离提示 4003） |
| 退药 | Pharmacy | 整方/部分退；展示原批次与可退量；退后自动冲正 |

### 5.7 计费域
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 诊疗项目目录 | 写:DrugAdmin | CRUD + 启停用（status） |
| 计费/账单 | 查:Billing；写:Pharmacy | 7 维筛选（来源/类型/患者/日期）；**一键计费**（from-prescription）；**红冲**（void）；负金额/红冲态展示 |
| 收费录入 | Pharmacy | 药品/耗材/诊疗项目手工计费（校验存在且启用） |

### 5.8 特殊药品域
| 页面 | 角色 | 关键功能 |
|------|------|---------|
| 专用处方登记 | Pharmacy | 麻精处方列表（类型/状态筛选） |
| 空安瓿回收 | Pharmacy | 登记/核对，与发药数联动 |
| 专账查询 | 查:登录 | 发药/退药台账（药/批号/月度） |

### 5.9 药学服务域（Pharmacy）
用药咨询 / 不良反应登记 / 用药指导 三组 CRUD 页面。

### 5.10 参考数据域（查:登录）
ICD-10 / 集采 / 医保 / 非医保 / 耗材五个检索页（keyword + 拼音码 + 筛选），供开方/药品录入复用（组件化）。

### 5.11 报表域（Report）
进销存汇总（期间选择）、效期分析（分档图表 ECharts）、特殊药品统计、调配工作量、拆零统计（量/损耗/毛利）、患者费用聚合。

## 七、开发进度规划

> 单人 4-6 周 / 双人 2.5-3.5 周；每个阶段以「可演示闭环」为里程碑，验收标准见右列。

| 阶段 | 周期(人日) | 任务 | 里程碑验收 |
|------|-----------|------|-----------|
| P0 工程与基础设施 | 3 | 脚手架、http 封装、类型生成、登录、布局、路由守卫、v-permission | M0：登录→角色菜单→401/403 处理可用 |
| P1 主数据 | 3 | 药品/分类/供应商/交互规则/参考数据检索页；DrugPicker、目录匹配 | M1：药品 CRUD + 医保/集采标注闭环 |
| P2 采购与库存 | 5 | 采购建议→采购单→收货入库；库存/调拨/拆零/盘点/预警/领用 | M2：入库→拆零→盘点→预警处理可走通 |
| P3 患者与处方（核心） | 6 | 患者/过敏史；开方（补全+交互面板）；处方列表/详情；审核；调配/发药；退药 | M3：建档→开方→审核→发药→退药全链路（含麻精双人） |
| P4 计费与药学 | 3 | 计费/红冲/一键计费；诊疗项目；咨询/不良反应/指导；五专页面 | M4：发药后可一键计费，退药自动冲正可见 |
| P5 报表与系统 | 3 | 6 报表 + ECharts；用户管理；操作日志；工作台 | M5：报表数据与后端抽样一致 |
| P6 联调与交付 | 3 | 7 角色全量走查、权限点核对、缺陷修复、构建部署、文档 | M6：冒烟脚本 + 人工走查通过，交付 |

**合计：约 26 人日**（含缓冲）。关键路径：P3（处方域）为风险最高、投入最大。

### 依赖顺序建议
```
P0 → P1 → P2 ─┐
              ├→ P3 → P4 → P5 → P6
P0 → P1 ──────┘
```

## 八、质量与工程化

| 项 | 标准 |
|----|------|
| 代码规范 | ESLint（vue-tsc strict）+ Prettier + husky pre-commit；CI 与后端并行 |
| 类型同步 | `types/generated` 由 `docs/swagger.json` 生成；后端接口变更 → 重生成 + 编译检查（与后端 CI 的 swagger 门禁呼应） |
| 单元测试 | composables/utils（money/format/权限点）≥ 主要逻辑；组件冒烟（Vitest） |
| 联调冒烟 | 复用 `scripts/smoke_test.py` 场景做前端全链路走查清单 |
| 构建 | `vite build` 产物静态部署（Nginx）；`/api` 反向代理到后端；CORS 生产限定域名（后端配置） |
| 版本 | 与后端同节奏：功能完成即发布，README/CHANGELOG 同步（双端规范一致） |

## 九、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 契约漂移（后端接口变动） | 联调返工 | types 由 swagger 生成 + 双端 CI 门禁；后端改动必须同步生成物 |
| 处方状态机交互复杂 | 按钮/状态错乱 | 前端仅按状态渲染（§4.5 表驱动），后端兜底；StateMachineActions 组件统一 |
| 金额精度 | 账务展示错误 | 全链路整数分，仅展示层格式化；MoneyText 单一出口 |
| 麻精合规（双人/五专） | 流程违规 | 前端强提示 + 后端强制校验（4003/2013）；走查清单覆盖 |
| 7 角色权限遗漏 | 越权/不可用 | 权限点清单与后端路由组映射表维护，P6 全角色走查 |
| 报表数据口径 | 数字不符 | 报表页标注口径（docs/04 §8），抽样核对 |
